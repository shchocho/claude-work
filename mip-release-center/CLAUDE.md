# 문서 해지 센터 — 작업 안내

Microsoft MIP로 보호된 문서를 자가 승인 후 해제하고, 사외 송부 기록을 파일 원본과 함께 남기는 앱이다.
구조, 저장 정보, 한계는 `README.md`에 있다. 큰 작업을 시작하기 전에 먼저 읽는다.

## 실행과 확인

- `npm run demo` — 예시 이력을 넣고 시작 (http://127.0.0.1:4300)
- `npm start` — 빈 상태로 시작
- `npm test` — API 테스트. 서버 로직을 바꾸면 `test/api.test.js`에 테스트를 더하고 통과시킨다.
- Node.js 22.5 이상. 데이터는 `data/`에 쌓이고 git에 올리지 않는다. 처음부터 다시 보려면 `data/`를 지운다.

## 지켜야 할 것

- **의존성을 추가하지 않는다.** 서버는 Node 내장 모듈(`node:sqlite` 포함)만 쓰고, 화면은 빌드 없는 ES 모듈이다.
  npm 패키지, 프레임워크, 외부 CDN·글꼴을 넣지 않는다(폐쇄망에서 그대로 동작해야 한다).
- **인라인 style 속성을 쓰지 않는다.** CSP(`style-src 'self'`)가 막는다. 데이터에 따라 달라지는 크기는
  `data-w` / `data-h` 속성으로 적고 `web/js/lib/dom.js`의 `mount()`가 반영한다.
- **화면 템플릿은 `dom.js`의 `html` 태그로 쓴다.** 끼워 넣는 값은 자동으로 이스케이프된다.
  불리언은 빈 문자열이 되므로 `aria-pressed` 같은 속성에는 `String(...)`으로 넘긴다.
- **코드값은 두 곳에 있다.** `server/consts.js`와 `web/js/lib/consts.js`. 한쪽을 바꾸면 다른 쪽도 맞춘다.
- **`web/` 아래에 파일을 추가하면 `web/sw.js`의 `SHELL` 목록에도 넣는다.** 빠지면 미연결 상태에서 앱이 열리지 않는다.
- **상태를 바꾸는 API 요청에는 `X-MRC-Client: 1` 헤더가 필요하다.** `web/js/lib/api.js`를 거치면 자동으로 붙는다.
- **감사 기록은 고치거나 지우는 기능을 만들지 않는다.** 감사 이벤트는 `server/audit.js`의 `record()`로만 덧붙인다.

## 디자인

- 색은 `web/styles/tokens.css`의 토큰만 쓴다. 의미가 정해져 있다:
  녹색(`--control-*`) = 시스템 통제 구간과 주요 동작, 황색(`--channel-*`) = 송부 수단, 적색(`--audit-*`) = 감사에서 주의할 것.
- 색을 바꾸거나 더하면 밝은 화면과 어두운 화면 모두에서 글자 4.5:1, 조작 요소 테두리 3:1 대비를 확인한다.
- 화면이 바뀌거나 단계가 넘어갈 때 포커스를 맞는 곳으로 옮긴다(새 제목, 첫 오류 입력, 완료 제목).
- 문구는 한국어로, "무슨 일이 났는지 → 왜 → 어떻게 하면 되는지" 순서로 쓴다.
  용어는 해제 / 송부 / 송부 수단 / 수신처 / 저장 정보로 통일한다. 버튼에는 동작 그 자체를 적는다.

## 아직 모의 구현인 것

1. **MIP 해제** — `server/mip/mock-adapter.js`만 실제로 동작한다. 실제 MIP 파일은 해제하지 못한다.
   `sidecar-adapter.js`가 위임할 서비스의 계약은 README의 "운영에 올리기 전에 바꿔야 할 것"에 있고, 그 서비스는 아직 없다.
2. **로그인** — 계정을 골라 들어가는 체험용이다(`server/app.js`의 세션 부분). Entra ID SSO로 교체해야 한다.
3. **메일 발송** — `server/connectors/mail.js`가 `data/outbox/*.eml`로만 남긴다.
4. **우회 반출 차단** — 범위 밖이다(엔드포인트 DLP의 몫).
